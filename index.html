SYSTEM OVERVIEW · 总览

01系统架构：智能在 GPU，控制权在本体

VLA / VLM 等重模型跑在局域网 GPU 服务器，本体只做控制与执行——分层为了算力，红线为了安全： 智能与实时控制解耦，所有运动指令由 Robot 本地仲裁与执行，这是全页所有设计的第一原则。

工程实现 源码、接口契约与失败注入测试共同约束 Robot / GPU 边界，远程服务不直接获得运动控制权。
当前代码边界：GPU 侧只返回 intent、bbox 或 action chunk，不发布 controller command，也不打开 Robot motor device；ACT action chunk 必经 Robot 本地 Streaming Executor——检查 session/时序、joint-state 新鲜度、关节限位、watchdog 和 controller 状态。这是软件安全机制，不等于认证安全机械或物理急停。

02抓取体系：标定 · 传统 · 学习 核心工作

项目围绕单臂抓取完成了标定误差分解、传统 RGB-D 顶抓原型，以及“MoveIt 预抓取 + ACT 局部动作”真机演示。 当前主 Demo 采用 ACT 路线，传统链路作为原型研究与方案对照保留。

2.1标定体系：先分解误差，再谈抓取精度

从“视觉点为什么到不了机械臂末端”出发，将问题拆成舵机零位、底盘几何、D455/头部外参和右臂手眼四套工作流，并为样本、求解、质量门和资产版本建立测试。

① 舵机零位 / 方向 / 行程

样本与 unit / model 绑定，记录 offset 和有效行程；软限位经运行时配置统一应用。真机扭矩释放、全行程和恢复需单独授权验收。

实现 + 契约 / codec / 安全测试

② 底盘几何标定

用多方向直行和旋转观测拟合轮径 / 轮距，输入数据经 schema 和 finite 检查，结果通过标定资产激活后再渲染到 runtime。

实现 + 资产拟合 / launch 测试

③ D455 / 头部外参

对固定 target 采集 moving-camera 多姿态观测，只查询 image timestamp 对应的 TF；使用 fiducial PnP、多初值候选和 6D 非线性精修，输出逐样本残差。

实现 + fiducial / sample / solver 测试

④ 右臂手眼 AX=YB

对 fixed-camera / moving-target 模型联解相机位姿与 tag 安装位姿；样本全历史去重，展示姿态覆盖与逐样本残差，便于检查异常姿态。

实现 + 合成求解 / node / 资产测试
历史原型实验的最大收获：用视觉链和 FK 链对同一物理点独立解算取差，曾用于发现平面 PnP 歧义、手眼模型选错、控制点混淆以及残差与关节角相关等问题。 这些记录最终沉淀成当前工作流中的 frame 检查、身份绑定、多初值候选、逐样本残差和独立复测原则。
决策与权衡：
  • 低 RMSE ≠ 模型正确：必须同时检查 frame 定义、板坐标和独立物理点；
  • 质量门 ≠ 实测精度：阈值是拒收条件，只有固定验证集和当前 unit 记录才能升级 claim；
  • 算法残差 ≠ 末端精度：还需把关节零位、回差、重力下垂和控制器到位误差分开；
  • 结果必须可回溯：标定版本、unit 身份、样本集和激活记录要成对保存。

2.2传统方案：历史原型探索

原型研究 冻结原型曾实现下述链路；当前主 Demo 将 GraspObject 收敛为 ACT 路线，传统方案作为设计和调试对照。

历史管线：指定物体 → VLM bbox + SAM2 分割 → RGB-D 目标点云 → GPD 抓取候选 / centroid fallback → 顶抓几何约束 → MoveIt 规划与 pick-place 试验。本页不将方案调研中的其他抓取模型写成已实现。

分割质量决定候选质量

VLM bbox 粗框 + SAM2 掩码用于从桌面场景中分离目标点云。分割失败会直接污染三维候选，因此要把 mask 质量作为独立观测而非黑盒输入。

三维候选与 MoveIt

原型使用 GPD HTTP 候选与 centroid fallback，再结合顶抓手腕 / 夹爪几何与 MoveIt 规划。这是应用与调试经验，不表述为抓取网络算法研发。

调试与复盘

用管线日志、中间可视化、真机视频和失败分类区分检测、分割、候选、规划与执行问题，避免将所有空抓笼统归因为“算法不准”。

2.3两阶段 ACT：确定性粗接近 + 学习闭环精抓

这是为了降低小规模示教下的任务难度而做的系统分解：大范围运动交给确定性规划，局部接触动作交给 ACT。 这一选择的目标是在小规模示教条件下收缩策略初始状态分布，并保留大范围运动的可解释性与本地安全约束。

阶段一：MoveIt pregrasp 粗接近

确定性、安全限位、可回归
  • IK 种子序列 → MoveIt 规划 → 本地碰撞 / 可达校验
  • 单点 4s 轨迹执行，实测关节到位才放行
  • 把臂安全合法地送到「门口」，不为此录几十条示教

阶段二：ACT 闭环精抓

桌面接触、物体滑移、位姿微调——解析建模性价比最低的部分
  • ACT 从实测 pregrasp 上下文启动
  • 推理起点与训练采集分布严格对齐，避免分布外初始状态
  • action chunk 经本地 Streaming Executor 执行（0.5s 看门狗）
  • VerifyGrasp 腕部复核 + 夹爪信号双判定，失败自动重抓
当前软件链路：双相机 + 关节状态采集（.incomplete 校验后原子发布） → 断点传输 → GPU 重校验与 LeRobot 转换 → 训练 / 恢复 / 评估 / 导出 CLI → 版本化 checkpoint 资产。采集、转换、训练 CLI、协议与本地执行分层测试，避免某一环通过就被误当成整链质量结论。 关键工程细节：用 predict_action_chunk 每请求取完整 action chunk—— select_action 的内部队列会吞掉随后 99 步的新观测，直接破坏闭环。
CONFIG · action[t] = follower_state[t+1] 末帧无后继状态，不生成 action Leader 用于遥操对齐，不作为训练状态 evaluate 是资格检查，非抓取成功率

03移动基础：建图与导航

为抓取和送达提供移动基础——先查物理标定与 TF，再调 SLAM / Nav2；把近桌对接从普通导航中拆出。

真机联调 完成过定位、导航到桌和低速近桌调整。 工程化沉淀 将定位质量门、scan-map consistency、恢复逻辑与可重复的验收步骤纳入能力接口和测试。

里程计物理标定（根因治理）

  • 1m 直线标轮半径、360° 原地旋转标轮距（验收 5–10%）
  • 固定「传感器 → TF → 里程计 → SLAM」排查顺序 + 症状速查表，不盲调 SLAM 参数
  • 雷达本体遮挡 mask 校准，屏蔽给 inf 而非假障碍
根因故事：轮距配置 0.25m vs 实际 0.49m → yaw 积分错 2 倍 → 转弯重影的真凶

slam_mapping_guard 异常防护（自研）

guard 把 scan 投影到当前地图做穿墙检测，三级输出而非简单阈值熔断： SUSPECT 只提示不锁车；CRITICAL（多束激光连续穿可信墙体）停发 scan + 暂停建图 + 软锁底盘， 阻止错误 free space 写进 pose graph。恢复走状态机：UNLOCK → 定位确认 → RESUME。

架构：lidar → /scan_raw → guard → /scan → SLAM

导航到桌面业务链

  • 桌位 / 送达点标注为命名地点，业务语义直接生成导航目标
  • 三阶段对接：Nav2 到桌旁 → Spin 收敛朝向 → 自研精确 dock 贴桌（含横向误差校正）
  • 定位质量门控：AMCL 协方差 + scan-map 一致性双条件，不达标自动重定位——坏定位不进任务
NavigateToNamedPlace / AutoLocalize

脱困与恢复

  • 卡住检测（15s 位移 < 0.1m）→ 恢复行为编排：清 costmap / 原地转 / 倒退，最多 6 轮
  • 差异化 inflation_radius：解决「门被膨胀堵死」
  • RotationShim + RPP 替换 MPPI：解决 CPU 卡顿导致的控制循环 miss
真机问题记录 → 配置与恢复策略 → 自动化回归
决策与权衡 · 为什么不自动回滚地图：快照 / 自动回滚只立架构策略、不在当前版本实施—— 自动回滚必须等定位 gate 足够可靠后再接入，否则可能把错误 pose graph 回滚成另一个不可解释状态。 异常处理的价值不在于「出事后自动动作」，而在于让每一步都可人工确认、可解释。

4.3面向验收的工程化

实现离线安装、版本切换、回滚、卸载和诊断工具，并用 fake-root / 离线生命周期测试验证失败路径。

离线 Release + 版本回退

SHA-256 manifest 校验；.staging 解包 + current 原子切换；重复安装幂等；安装后以 offline doctor 作门禁，失败回退。

xlerobotctl install-release / rollback
双模式卸载

--keep-assets 保留配置 / 资产 / 日志；--purge 对服务、规则、用户、目录逐项确认无残留。

uninstall.sh --keep-assets | --purge
诊断与日志纪律

doctor 结构化体检；support-bundle 脱敏打包支撑远程定位；持久日志统一 /var/log/xlerobot + logrotate；任务级 JSONL trace 带唯一 task_run_id。

xlerobotctl doctor / support-bundle
四 Profile 互斥

demo / mapping / calibration / collection 固定 launch 组合，systemd Conflicts + flock 双重互斥，同一时刻只有一个 profile 持有硬件。

xlerobotctl start demo

4.4工程方法：我怎么工作

从现象到回归

将空抓、导航朝向偏差和取消竞态等真机现象转成可解释的状态、错误码和回归测试。

契约与测试

用 typed Action / Service / Message 限定能力边界，配合 mock、dry-run、契约测试和失败注入锁定已验证行为。

AI 辅助与个人责任

使用 AI 辅助资料检索和部分实现；我负责需求取舍、架构、代码审阅、实验和对外证据边界。

本地执行权

远程 VLM / 策略服务只返回结构化结果；运动指令由本地运行时统一校验所有权、新鲜度、限位和 watchdog。
